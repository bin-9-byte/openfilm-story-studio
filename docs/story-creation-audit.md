# 剧本分线与导演场次：通用性复查

日期：2026-11-22。范围：当前浏览器本地版的数据结构、创作入口、正文引用、全片串读与场内分镜。此次为代码与方法论对照复查，未新增运行时功能，也未重新进行全套浏览器实测。

## 后续实施更新

下文保留为改造前的复查基线。本轮已补上独立正文与稳定段落、场次／镜头段落引用、同正文多线呈现和空场次／空镜头入口，并以原片样例通过浏览器实测。尚未补齐独立串读顺序、事件时间、拍摄单元、多集容器和长片规模性能验证。具体入口见 `story-first-interaction.md`，后续事项见 TODO。

## 结论

当前适合作为线性叙事短片的创作基础，也能表达多线并行和跨场节拍；尚不足以成为覆盖所有短片、长片与剧集的通用创作模型。主要约束来自正文与时间片段绑定、整卡引用、单层连续场次和缺少跨集容器。继续沿用剪辑式轨道操作是可行的，但需要让内容身份与它在时间轴上的出现位置逐步分离。

当前原片验证证明了该样例的编辑、引用、分镜与离线恢复流程；不能据此推断所有叙事形式都已覆盖。

## 方法论依据与使用边界

参照本机 `screenwriting-master/SKILL.md` 及其 `references/core-methodology.md`、`format-ultrashort.md`、`format-short.md`、`format-feature.md`、`format-series.md`。

- 核心方法论：戏剧动作、视听写作、外部情节与内在情感的双轨节奏、预估时长。
- 概念超短片：允许以形式和概念为入口，人物、完整场景拆解可以简化，支持循环、并置等形式。
- 短片：从戏剧动作到场景，再进行场景写作；专业场景本身也是编剧工作的一部分。
- 长片：结构方法有多种，需序列、人物弧光、副线与伏笔管理。
- 剧集：季与集的双层结构，以及角色状态、信息释放、伏笔与集间连续性。

这些资料是本产品的设计输入，并非所有作品都必须遵守的行业定律。例如 A/B 在中点交汇、每场必须价值翻转、固定时长比例，应作为可选模板和诊断意见，不能写成强制校验。技能中的逐步确认流程用于生成剧本，本次产品复查不据此强制用户逐步审批。

## 当前已有且应保留的能力

| 能力 | 已有实现 | 适用边界 |
| --- | --- | --- |
| 无场次写作 | 节拍可独立创建与编辑正文，自定义故事线 | 仍须落成一个有预计时长的时间片段 |
| 多线与跨场 | 同轨单行并在碰撞时推后；节拍可跨场；操作跟随与来源引用分别表达 | 轨道位置表达呈现位置，不能完整表达事件关系 |
| 场次引用正文 | 已确认来源按节拍 ID 保留，正文变化、移动或删除可核对，保留上次快照 | 引用单位是整张节拍卡 |
| 分镜独立设计 | 镜头描述、画面、景别、运镜、备注、时长和镜头节拍关联 | 一个镜头能关联多个节拍，仍归属于一个场内工程 |
| 全片检查 | 正文串读、分镜总览、定位和预计／实排时长核对 | 串读依赖节拍起点排序，尚不是独立完成的剧本文稿 |

## 主要局限及具体反例

### 1. A/B 是一种组织视图，不能成为唯一正文结构

同一个动作可能同时推进外部任务、关系和人物成长。当前节拍是轨道里的一个 clip，缺少一个正文块同时归属多条线的显式关系。复制两张卡虽然能画出来，却会形成两份可分别改写的正文。

建议：保留故事轨道和其碰撞规则；增加共享正文身份与多线标签／引用。情绪、伏笔、人物状态应有适合的标注视图，不必全部变成互斥时间卡。技能的“双轨节奏”指两项强度维度，也不等于 A/B 两条情节线。

### 2. 当前“选区划为场次”选的是时间范围，不是正文中的几句话

`sceneRange` 使用时间选区或所选卡片的最早起点和最晚终点；`createScene` 引用此区间里所有重叠节拍。若 A/B 同时存在，选 A 的一张卡也可能把重叠 B 卡纳入来源，创建前会列出候选，之后可人工调整。

一个节拍写“街口收到信 → 邮局拆信”，划成两场后，两场都会看到整段，无法只引用各自一句。修改整卡又会让所有引用场次待核对，粒度偏粗。

建议：增加稳定正文块与范围引用；明确区分“时间选区”和“正文选区”，创建前允许勾选来源。移动关联、剧本来源和镜头服务的节拍继续分开表达。

### 3. 一套时间坐标尚不能表达所有叙事顺序

当前起点和时长既用于剧本节拍，也用于场次安排。故事实际发生的先后、观众看到的先后、拍摄先后没有独立建模。全片串读按起点排序，仅相同起点并列；A 为 0—30 秒、B 为 10—20 秒时，会先显示完整 A，再显示 B，不会自动得到 A 前半 → B → A 后半的连贯文稿。

建议：时间轴继续表示观众呈现时间；正文串读顺序、事件发生顺序和拍摄计划分别建立可选关系。同一事件闪回两次，使用两个呈现片段引用同一来源，而非复制事件正文。

### 4. 剧本场景、导演拆解和生成任务仍需区分

“先有剧本”应表示支持先写未拆分的内容；用户也可以一开始就按内／外景、地点、日夜写场景。场景创作既可以发生在编剧阶段，也可以在导演阶段进一步拆解。

当前新建场次必须覆盖至少一个节拍，且不能与现有场次时间重叠。场次是一个连续时间片段，镜头是该场内独立工程中的片段。这套组织对普通短片有效，但尚无专门机制表示：

- 两地电话交叉剪辑：同一叙事段落涉及两个空间，两个场景在成片中反复交错。
- 一个长镜头由室内走到室外：连续镜头覆盖多个场景／拍摄单元。
- 蒙太奇跨数周和多个地点：一个叙事段落包含多组拍摄资料。
- 一场戏分多个生成任务，或一个生成素材被不同镜头／版本引用。

建议：逐步区分叙事场景、拍摄／生成单元与成片出现片段，并以引用连接；不要求成片同一画面轨重叠，也不自动把同一故事线拆多行。先增加独立空场次与空镜头入口，允许纯视觉构思先行。

### 5. 早期构思不应强制确定秒数

新增节拍默认 4 秒，新增镜头也默认 4 秒。虽然这是可修改的初始值，但模型没有“尚未估时”状态。导演修改场内实排后，可以采用镜头时长并推后场次，而不会同步移动正文；已确认来源仍保留，但两个时间安排可能逐渐分离。

建议：支持待定时长／暂存卡；同时保留预计时长和实排时长。采用实排前展示影响范围，允许明确选择后续如何处理，整次操作可撤销。声音跨镜的设计另见声音 TODO。

### 6. 能填写分镜表，还不等于覆盖完整导演创作

当前有画面、描述、景别、运镜、备注和关联节拍，是可用的分镜表基础。场次地点是自由文本；角色、日夜／内外景、场面调度、视线与轴线、镜头目的、连续性和方案版本尚无专门结构。可以写在备注里，但难以筛选、关联和核对。

建议：按需要渐进显示导演字段、调度图／参考与方案；声音设计保持独立待办。避免一次把全部专业字段铺到主界面。

### 7. 长片和剧集缺少上层组织与连续性

现模型的专业实体集中在 beat／scene／shot；没有专用幕／序列／季／集容器，也没有角色状态与伏笔回收关系。可用多个工程人工管理多集，但这不等于具备跨集连续性。场号在部分总览按当前排序生成，不能取代长期稳定的拍摄场号。

建议：先补序列分组与稳定场号，再加入季／集和连续性记录。梗概、人物、世界观和结构模板可以作为独立资料，而不是强制塞到时间轴上。

## 验收反例：后续实施时逐项验证

以下为设计验收用例，未宣称全部通过。

| 场景 | 当前覆盖程度 | 后续通过标准 |
| --- | --- | --- |
| 普通叙事短片，多线节拍跨场 | 已有基本支持 | 保留当前拖拽、吸附、推后、关联和整次撤销 |
| 一个节拍的两段文字分属两场 | 只能引用整卡 | 每场指向具体段落，正文改写仍可追踪 |
| 一场告别同时推进关系线和任务线 | 镜头可多节拍关联；正文多线共享缺口 | 一份正文，多线可查看与定位，改写不产生两份正文 |
| A 前半 → B → A 后半的电话交叉剪辑 | 可人工拆卡；无独立呈现引用 | 文稿可连贯串读，来源事件不需复制 |
| 同一事件先片段闪回、后完整揭示 | 可人工复制／关联；无专门重现模型 | 多次呈现共享来源，可分别调整片段与揭示信息 |
| 无对白的纯视觉概念片，从空镜开始 | 新场次入口受节拍前置限制 | 可直接开始场次／镜头，并随后补内容关联 |
| 长镜头跨室内外，蒙太奇跨多地点 | 缺少跨单元镜头关系 | 连续呈现与拍摄拆解可分别管理，无需伪造剪切 |
| 多集共同人物、伏笔与季末回收 | 需工程外人工维护 | 分集可独立编辑，跨集状态／伏笔有明确来源 |

所有新增关系均须覆盖旧工程兼容、本机自动保存、断网重开、完整备份导入导出与整次撤销。专业模板提供建议与检查，不强制一种结构理论。
