# 幕／序列与稳定场号

2026-11-22。浏览器本地版与本机版共用原生编辑操作，分组不替代剪辑轨道。

## 使用入口：直接操作左侧目录

1. 左侧点「+ 幕」或「+ 序列」，填写名称并创建。幕旁边的「+」直接在该幕下创建序列，不需要再选择类型或所属幕。
2. 把场次拖到某个幕／序列的标题上即可归组；拖到「未归组」即可移出。长目录拖拽时，停在目录上／下边缘会自动滚动。只改变归属，不移动底部时间轴。所选的多张场次可以一起拖动。
3. 每张场次卡直接显示场号、时间和当前归属；目录底部持续显示选中场次的场号和完整归属路径。归组后目录即时更新；撤销／重做也会同步更新。
4. 条目旁「⋯」管理当前对象。幕／序列可重命名、上移／下移、移动到其他幕或删除。场次可通过「移动到…」选择真实的当前归属，也可修改场号；这是不拖拽时的操作方式。
5. 删除幕时，其子序列会保留为独立序列；删除分组保留所有正文、场次和分镜。删除分组并不删除内容。
6. 新工程的场次自动编号。旧工程若显示「未编号」，左侧点一次「编场号」；也可直接在选中场次下方「修改场号 → 保存场号」。
7. 全片总览仍可按幕筛选其子序列与场次，场内分镜仍显示所属场号与分组路径。

原来正文区的「幕／序列与场号」大面板已移除，创建、移动、管理和场号编辑都在左侧完成。幕和序列是可选分组，不要求先完成分组才能写作。

界面统一使用「故事卡 → 场次 → 镜头」。原先的“节拍”在界面中称为故事卡，后台 `beat` 类型、正文 ID 与既有工程关系不变；不批量改写用户自定义名称。分组排序仅影响目录与场次总览，底部仍按实际呈现时间剪辑。

## 场号规则

- 旧工程没有场号时显示「未编号」。点击目录的「编场号」或首次新增幕／序列，按现有场次时间顺序分配 S001、S002 等；这是一个可撤销的操作，不在打开页面时自动改写工程。
- 新建场次会确保场号体系存在并分配新号。之后场次无论移动到哪里，场号都跟随场次身份，不按场序重排。
- 场次选中时，可在左侧直接「修改场号」，例如 12A。全工程唯一，大小写视为同号；允许数字、字母、中文和 `. _ -`，最多 32 字符。
- 删除场次仍保留其场号登记和计数；新增场次不占用这个旧号。撤销删除恢复同一身份和场号。
- 分割场次时左半保留原号，右半分配新号并继承分组；一次撤销恢复完整场次、分组与编号状态。复制／插入获得新身份的场次也会分配新号。
- 撤销整个“创建场次”操作会同时恢复操作前的编号状态；重做会重现相同场次与场号。
- 分镜镜号仍为场内排序；本轮稳定的是场号，不把镜头序号冒充稳定镜号。

## 保存与兼容

工程级可选 `storyStructure` 包含分组、以片段 ID 为键的成员关系、以场次 ID 为键的场号登记以及下一个默认号。它与独立正文 `screenplay` 分开，并编码为 `film.html` 中不执行的 metadata，原生轨道与 clip 格式保持不变。

所有修改走现有编辑事务与会话撤销。原生场次分割／插入结束后统一分配缺失的场号；撤销同时恢复隐式产生的编号与分组变更。正文来源和场内分镜不因分组更改而移动或改写。

IndexedDB 自动保存、离线应用、完整工程 `.openfilm.json` 备份和完整工程文件夹导入均携带该 metadata。旧工程不批量覆盖正文或调整场次位置。刷新／重启不保证恢复原编辑器的会话撤销栈。

- 断网刷新、完整工程导出／导入、关闭浏览器后离线重开恢复结构与分镜。
